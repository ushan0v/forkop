# URLTest

Группа, которая держит самый быстрый рабочий сервер секции. В неё попадают серверы этой секции, а какие именно, решает **Фильтр серверов**, устроенный так же, как [фильтр подписки](/connections/subscriptions#фильтр-серверов).

## Как выбирается сервер

Раз в **Интервал проверки** группа замеряет задержку каждого сервера и берёт самый быстрый. На другой сервер она переходит, только если тот быстрее текущего больше чем на **Разницу задержки**. Если соединения через выбранный сервер начинают падать, группа проверяет серверы сразу, не дожидаясь интервала.

| Параметр | По умолчанию | Что задаёт |
| --- | --- | --- |
| **URL проверки** | `https://www.gstatic.com/generate_204` | адрес для замера задержки |
| **Интервал проверки** | `3m` | как часто проверять серверы |
| **Разница задержки** | `50` | на сколько миллисекунд другой сервер должен быть быстрее, чтобы группа на него перешла |
| **Ожидаемый статус** | `*` | какие HTTP-коды считать успехом, например `204/200-299`. `*` значит любой ответ |
| **Таймаут простоя** | `30m` | через сколько остановить проверки, если через группу ничего не идёт |
| **Прерывать соединения** | выключено | закрывать открытые соединения при переходе на другой сервер. Включите, если после переключения старые соединения зависают на упавшем сервере |

Какие серверы попали в группу и какой выбран сейчас, показывает кнопка ⓘ на карточке группы на вкладке **Дашборд**.

## URLTest или Fallback

URLTest выбирает по задержке, при включённом отборе — среди серверов с достаточной скоростью скачивания. Если серверы не равноценны, например свой сервер и запасная подписка, или нужен строгий порядок переключения, используйте [Fallback](/connections/fallback).

## Отбор по скорости скачивания

**Правило выбора по скорости** позволяет выбрать два режима. «Отбор по скорости, выбор по задержке» сохраняет исходное поведение. «Рейтинг по скорости, при близких значениях — задержка» сначала сравнивает Мбит/с допущенных доступных узлов. При допуске близких скоростей 20% в финальную выборку входят узлы со скоростью не ниже максимальной, делённой на 1,2; между ними выбирается задержка. Поэтому 229 Мбит/с выигрывает у 167 Мбит/с независимо от пинга, а при 229 против 210 Мбит/с решает задержка.

**Адаптивные проверки скорости** добавляют частую проверку выбранного TCP/UDP-узла (совпадающие узлы измеряются один раз). **Интервал проверки выбранного сервера** по умолчанию 10 минут; запуск происходит на ближайшем активном проходе URLTest, поэтому при проверке задержки каждые 3 минуты — обычно раз в 12 минут. При плохом результате проверка повторяется до подтверждения; при подтверждённой просадке перепроверяется до трёх доступных запасных узлов, начиная с наиболее быстрых по предыдущим замерам. После первого успешно допущенного запасного узла проверка останавливается. Полный обход по общему интервалу и ручная кнопка сохраняются.

В настройках URLTest включите **Отбирать серверы по скорости скачивания**. По умолчанию опция выключена: обычные группы не расходуют трафик на скачивание.

Задайте HTTP(S)-адрес достаточно большого файла, минимальную скорость в Мбит/с, интервал, таймаут, лимит объёма на сервер и число последовательных результатов. По умолчанию: 50 Мбит/с, 6 часов, 10 секунд, 32 МиБ и два результата. Первый проход делает по два замера каждого нового сервера, последующие — по одному. Для 10 серверов это до 640 МиБ при первом проходе и до 320 МиБ при каждом следующем.

Ядро скачивает данные через каждый сервер напрямую, не переключая рабочий маршрут. Замеры выполняются последовательно, даже если включены в нескольких группах. Ответы HTTP с ошибкой и слишком короткие ответы не считаются успешными. Таймаут ограничивает длительность скачивания. Скорость включает время установления соединения.

После нужного числа хороших результатов сервер допускается к выбору; после такого же числа плохих — исключается. Среди допущенных серверов действует выбранное правило: задержка или рейтинг скорости с задержкой для близких скоростей. Если нет допущенных доступных серверов, сохраняется обычный выбор по задержке. Новые соединения переходят на выбранный сервер; поведение уже открытых определяет **Прерывать соединения**.

На **Дашборде** откройте ⓘ у URLTest: там видны скорость, допуск и время замера (при наведении), а также кнопка **Проверить скорость скачивания**. Повторное нажатие во время проверки не запускает дополнительную загрузку. Результаты хранятся в памяти и сбрасываются при перезапуске ядра. В простое плановые проверки останавливаются вместе с URLTest; ручная проверка доступна независимо от простоя.

Проверяется HTTP-скачивание с выбранного источника, а не скорость UDP и не каждый видеосервер YouTube. Перегруженный источник или домашний канал могут снизить результат всех узлов. Для новой опции нужна сборка sing-box-forkop с поддержкой `bandwidth_test`; старые сборки не принимают это поле.
