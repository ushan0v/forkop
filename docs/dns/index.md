# DNS

DNS-серверы задаются на вкладке **Настройки**. Они отвечают на домены секций Bypass и на домены вне секций, а ещё через них ядро узнаёт адреса для своих соединений.

## Форматы

Протокол сервера задаётся префиксом.

| Запись | Протокол | Особенности |
| --- | --- | --- |
| `77.88.8.8` или `udp://77.88.8.8` | обычный DNS | самый быстрый, но провайдер видит запросы и может подменить ответ |
| `tcp://77.88.8.8` | обычный DNS по TCP | пригодится, если провайдер режет DNS по UDP |
| `tls://dns.google` | DNS over TLS | шифрованный, но идёт на порт 853, и провайдеру его легко заблокировать |
| `https://dns.google/dns-query` | DNS over HTTPS | шифрованный и похож на обычный HTTPS, его труднее всего заблокировать |
| `quic://dns.adguard-dns.com` | DNS over QUIC | шифрованный и быстрый, но его поддерживают не все серверы |
| `h3://dns.google/dns-query` | DNS over HTTPS через HTTP/3 | как DNS over HTTPS, только поверх QUIC |

Порт пишется через двоеточие, например `tls://1.1.1.1:853`. Путь бывает только у `https://` и `h3://`.

Сервер, заданный именем, как `dns.google`, сначала нужно найти, и это делают Bootstrap DNS-серверы. Серверу, заданному адресом, как `https://1.1.1.1/dns-query`, они не нужны.

## Основные и Bootstrap

**DNS-сервер** задаёт основные серверы, по умолчанию `77.88.8.8`, это Яндекс. Несколько серверов страхуют друг друга, см. [DNS Fallback](#dns-fallback).

**Bootstrap DNS-серверы** находят адреса основных серверов, заданных именем, и адреса серверов прокси при включённом **DNS через секцию**. Сами они задаются только IP-адресом, по умолчанию тоже `77.88.8.8`.

## DNS через секцию

**DNS через секцию** отправляет запросы основных серверов через выбранную секцию. Провайдер не видит запросов, а сайты получают адреса так, будто запрос пришёл из страны сервера. Bootstrap-серверы по-прежнему ходят напрямую.

## Статичные записи

**Статичные DNS записи** работают как файл hosts и задают домену постоянный адрес. В строке пишется адрес, а через пробел один или несколько доменов.

```text
# адрес        домены
192.168.1.20   nas.home media.home
10.8.0.1       vpn-gateway.corp
```

- Запись совпадает только с точным именем, поддомены она не охватывает.
- Адрес бывает IPv4 или IPv6. Чтобы дать домену несколько адресов, напишите их разными строками.
- Комментарии начинаются с `#` или `//`.
- Запись срабатывает после секций, поэтому домен, который забрала секция, получит ответ секции.

Так удобно дать имя домашнему устройству или закрепить за доменом адрес, который DNS отдаёт неправильно.

## DNS Fallback

Если в поле DNS-сервера указать несколько серверов, они страхуют друг друга. Не ответил один сервер или ответил ошибкой, ответ даст другой, и устройства этого не замечают.

Так работают **DNS-сервер** и **Bootstrap DNS-серверы** на вкладке **Настройки**, **DNS-сервер** у [DNS-секции](/sections/#dns) и у **Резолвера доменов** [сетевого интерфейса](/connections/interface). Когда серверов в списке больше одного, рядом появляется режим опроса.

**Параллельно**, по умолчанию. Запрос уходит всем серверам сразу, и ядро берёт первый хороший ответ. Упавший или медленный сервер ответ не задерживает.

**Последовательно**. Серверы спрашиваются по очереди, в порядке списка. Следующий получает запрос, только если предыдущий не ответил или ответил ошибкой. Поставьте основной сервер первым, а запасные за ним.

Ответ «такого домена нет» тоже считается ответом, и другие серверы его не перепроверяют.

| Задача | Серверы | Режим |
| --- | --- | --- |
| DNS не должен пропадать, если один сервер заблокируют | `https://dns.google/dns-query` и `https://cloudflare-dns.com/dns-query` | Параллельно |
| фильтрующий DNS, а при его сбое обычный | `https://dns.adguard-dns.com/dns-query`, затем `77.88.8.8` | Последовательно |

Фильтрующий DNS не ставьте в параллельный режим рядом с обычным. Ответ придёт от того, кто быстрее, и реклама будет то блокироваться, то нет.

## Внешний DNS-сервис

По умолчанию Forkop перехватывает TCP/UDP-запросы на порт 53 от устройств на выбранных **Сетевых интерфейсах источника**. Если перед Forkop должен стоять AdGuard Home, Pi-hole или другой DNS-сервис, отключите **Перехватывать DNS клиентов** на вкладке **Настройки**. Запросы пойдут на выбранный устройством DNS-сервер с исходными IP клиентов. Сам DNS роутера продолжит обрабатываться как раньше.

Например, AdGuard Home на роутере принимает запросы клиентов, а Forkop выбирает для них дальнейший маршрут:

```text
клиенты → AdGuard Home 192.168.1.1:53 → Forkop 127.0.0.42:53 → upstream DNS
```

1. В DHCP выдайте клиентам адрес AdGuard Home, в примере `192.168.1.1`.
2. Настройте AdGuard Home слушать адрес LAN роутера, сохранив `127.0.0.42:53` для Forkop. Слушатель на всех адресах может занять этот порт.
3. Укажите `127.0.0.42:53` как upstream DNS в AdGuard Home и отключите **Перехватывать DNS клиентов** в Forkop.
4. В **DNS-сервер** Forkop укажите публичные DoH-серверы или адрес отдельного AdGuard Home в LAN. У [DNS-секций](/sections/#dns) могут быть свои серверы. Конечный upstream не должен пересылать запросы обратно входному AdGuard Home.

AdGuard Home увидит IP клиентов и сможет показывать их имена, если они известны ему из DHCP или других источников. Forkop получит пересланные запросы от AdGuard Home, поэтому его DNS-условия **Только для устройств** и **Весь трафик устройств** не смогут различать исходных клиентов. Доменные правила без ограничения по устройствам продолжат работать.

Когда перехват отключён, устройства могут обращаться и к другим DNS-серверам напрямую. Чтобы доменные правила Forkop работали через FakeIP, запросы должны доходить до DNS Forkop. Шифрованный DNS клиентов эта настройка не перехватывает ни в одном положении.

В UCI переключатель задаётся так; отсутствие параметра означает включённый перехват:

```sh
uci set forkop.settings.intercept_client_dns='0'
uci commit forkop
/etc/init.d/forkop reload
```

Чтобы вернуть перехват, задайте `intercept_client_dns='1'` и примените настройки снова. Новые правила действуют на новые DNS-соединения; существующие NAT-состояния могут сохраняться до их завершения.

Остальные параметры DNS описаны на странице [Настройки](/settings#dns).
