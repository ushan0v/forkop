# Настройки

Все параметры вкладки **Настройки** по порядку. В скобках стоит имя параметра в разделе `settings` файла `/etc/config/forkop`.

## DNS

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **DNS-сервер** (`dns_server`) | `77.88.8.8` | основные DNS-серверы. Протокол задаётся префиксом, несколько серверов страхуют друг друга. [Подробнее](/dns/) |
| **Режим опроса основного DNS** (`dns_main_fallback_strategy`) | Параллельно | спрашивать несколько серверов сразу или по очереди |
| **Bootstrap DNS-серверы** (`bootstrap_dns_server`) | `77.88.8.8` | узнают адреса DNS-серверов, заданных именем, и серверов прокси. Только IP-адреса |
| **Режим опроса Bootstrap DNS** (`dns_bootstrap_fallback_strategy`) | Параллельно | то же для bootstrap-серверов |
| **Перезапись TTL для DNS** (`dns_rewrite_ttl`) | `60` | сколько секунд устройства хранят ответ |
| **Стратегия DNS** (`dns_strategy`) | Предпочитать IPv4 | какие адреса ядро запрашивает для своих соединений |
| **DNS через секцию** (`dns_detour_enabled`, `dns_detour_section`) | выключено | отправлять запросы основных DNS-серверов через секцию |
| **Статичные DNS записи** (`static_hosts_text`) | пусто | постоянные адреса доменов в формате hosts |
| **Тайм-аут DNS** (`dns_timeout`) | `10s` | сколько ждать ответа DNS-сервера |
| **DNS вне правил** (`unmatched_dns_mode`) | Forkop | кто отвечает на домены вне секций. **Forkop** отвечает основными DNS-серверами, **Роутер** отдаёт их dnsmasq со всеми его настройками, например AdGuard Home |

## Сеть

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Исключить устройства из маршрутизации** (`routing_excluded_ips`) | пусто | устройства, которых Forkop не трогает: ни трафик, ни DNS. Пункт **Система** означает сам роутер |
| **Сетевой интерфейс источника** (`source_network_interfaces`) | `br-lan` | откуда Forkop забирает трафик устройств. Гостевую сеть добавляют сюда, если она должна идти через Forkop |
| **Включить выходной сетевой интерфейс** (`enable_output_network_interface`), **Выходной сетевой интерфейс** (`output_network_interface`) | выключено | через какой интерфейс ядро выходит в интернет. Без настройки соединения ядра идут по маршрутам роутера, как у любой другой программы, с отдельными маршрутами к серверам, mwan3 и политикой маршрутизации. Задавайте интерфейс, только если ядро должно выходить через него в обход маршрутов. В списке те же провайдеры и туннели, что у поля [Сетевой интерфейс](/connections/interface#что-есть-в-списке) секции |
| **Мониторинг интерфейса** (`enable_badwan_interface_monitoring`) | выключено | следить за WAN-интерфейсами и применять конфигурацию заново, когда интерфейс снова поднимается. Помогает, если после переподключения провайдера ядро теряет интернет |
| **Наблюдаемые интерфейсы** (`badwan_monitored_interfaces`) | пусто | за какими интерфейсами следить |
| **Задержка при мониторинге интерфейсов** (`badwan_reload_delay`) | `2000` | сколько миллисекунд ждать после поднятия интерфейса |

## Трафик

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Включить YACD** (`enable_yacd`) | выключено | панель [YACD](https://github.com/MetaCubeX/Yacd-meta) по адресу `http://<роутер>:9090/ui`: соединения, группы и логи в интерфейсе Clash. При первом включении ядро скачивает панель с GitHub. Ссылка под переключателем открывает панель уже с ключом Clash API |
| **Включить доступ YACD WAN** (`enable_yacd_wan_access`) | выключено | открыть панель и Clash API на всех интерфейсах, а не только дома. Порт нужно отдельно открыть в файерволе |
| **Ключ Clash API** (`yacd_secret_key`) | выключено | без него Clash API не отвечает, поэтому чужие устройства в сети не видят соединения и не переключают серверы. С этим ключом входят YACD и другие клиенты Clash API. Пустое поле Forkop заполнит новым ключом при следующем запуске или применении настроек |
| **Отключить QUIC** (`disable_quic`) | выключено | отклонять QUIC, то есть HTTP/3 по UDP, в перехваченном трафике. Браузеры перейдут на TCP, это помогает, когда видео через VPN тормозит |
| **Торренты напрямую** (`bittorrent_direct`) | выключено | соединения BitTorrent, распознанные в перехваченном трафике, отправлять напрямую мимо секций |

## Обновления

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Автообновление наборов правил** (`list_update_enabled`) | включено | обновлять встроенные списки и удалённые наборы правил по расписанию |
| **Период обновления списков** (`update_interval`) | `1d` | как часто, например `12h`, `1d` или `3d` |
| **Точное измерение задержки** (`unified_delay`) | включено | засчитывать второй запрос через уже открытое соединение, без установки соединения и рукопожатий |
| **URL для тестирования задержки** (`latency_test_url`) | `https://www.gstatic.com/generate_204` | адрес для проверки задержки на дашборде |
| **Скачивать списки через секцию** (`download_lists_via_proxy`, `download_lists_via_proxy_section`) | выключено | скачивать встроенные списки и удалённые наборы правил через секцию |
| **Запрашивать WARP через секцию** (`warp_profiles_via_proxy`, `warp_profiles_via_proxy_section`) | выключено | регистрировать и получать профили Cloudflare WARP через секцию. [Подробнее](/tunnels/warp#создать-туннель) |

## Служба

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Путь к файлу конфигурации** (`config_path`) | `/etc/sing-box/config.json` | куда Forkop пишет конфигурацию ядра. Во флеш-памяти она переживает перезагрузку, в `/tmp` не расходует флеш-память и собирается заново при запуске |
| **Путь к файлу кэша** (`cache_path`) | `/tmp/sing-box/cache.db` | кеш ядра: FakeIP, скачанные списки и подписки, ручной выбор серверов, профили WARP. В `/tmp` он пропадает при перезагрузке, во флеш-памяти сохраняется, но постоянно её перезаписывает |
| **Уровень логов** (`log_level`) | `warn` | подробность журнала ядра: `trace`, `debug`, `info`, `warn`, `error`, `fatal`, `panic`. На строки самого Forkop не влияет |

::: warning Кеш во флеш-памяти
Ядро пишет в кеш постоянно: каждый новый домен FakeIP и каждое обновление списков. На недорогих роутерах это изнашивает флеш-память, поэтому без особой причины держите кеш в `/tmp`.
:::
